mcp

      
Conectar un server MCP

      
El comando arranca el server por stdio (formato Claude Code/Cursor). Queda guardado en .lampson/mcp.json y sus tools entran al catálogo del agente como mcp_<server>_<tool>.

      
      
      
      
      

    

  

  

    

      
lámparas
Lámparas

      

        

          
          

          

        

        

      

      

        
Herramientas hechas a medida para este proyecto

        
Una lámpara es una tool que el agente (o vos) escribe para este repo: una carpeta con lamp.json y el código — en Synsema (corre bajo un techo de capacidades que no puede superar) o en cualquier lenguaje (python, node, un binario). A diferencia de un script suelto, el modelo la ve en su catálogo con parámetros tipados, vos la podés correr desde acá, y queda en el repo para la próxima sesión.

        
Pedila en el chat — «hacé una lámpara que liste los endpoints del backend». El agente la escribe en .lampson/lamps/, la valida y te pide encenderla acá.

        
Encendida = existe — apagada, el agente ni la ve. Al encenderla, sus tools entran al catálogo como lamp_<lámpara>_<tool> desde el próximo turno. Las globales viven en lamps/ y valen para todos los proyectos.

        
Ejemplos

        
    
          
  • Consultas del proyecto — endpoints() que parsea tus rutas y devuelve método + path + handler; env_keys() usadas vs. definidas en .env.example.
    • 
          
  • Generadores con tus convenciones — new_component(name) que crea el .tsx + test + story con tu plantilla exacta.
    • 
          
  • Checkers — check_i18n() claves faltantes por idioma; lint_styles() colores hardcodeados fuera de tus tokens.
    • 
          
  • Datos locales — db_schema() / query(sql) contra tu SQLite con techo db=./dev.db.
    • 
          
  • Integraciones sin MCP — deploy_status() contra tu API con techo net=api.x.com.
    • 
        

        

      

      
    

  

  

    

      
lsp

      
Agregar un language server

      
El mismo proceso que usa tu editor para «ir a definición». El agente lo usa para ver la estructura de un archivo sin leerlo entero (symbols) y para navegar sin ambigüedad (definition, references, hover). No se instala nada acá: elegí un preset (con npx se baja solo) o poné tu comando. Arranca en la primera consulta.

      
      

        
        
        
      

      

      
      

    

  

  

    

      
programadas

      
Programar una tarea

      
Corre sola, a la hora que digas, en el proceso residente de Lampson (lampson --daemon start o esta web abierta). También podés pedírsela al agente en el chat: «todos los días a las 9 corré los tests y avisame».

      
      
      
      

        
        
      

      

        
      

      

        
        
      

      
      
Sobre de permisos de una corrida sin nadie mirando. En «preguntar», la aprobación aparece acá y, con LAMPSON_PUBLIC_URL + LAMPSON_WEBHOOK_URL, como link en tu canal; sin respuesta en 2 h se deniega. Lo destructivo del sistema se bloquea siempre.

      
      

      

    

  

  

    

      
configuración
Configuración

      
GeneralAprobaciones a distanciaProveedor

      

        
Se guarda en lampson/.lampson/config.json (local). Un valor fijado en .env gana y se muestra bloqueado.

        
      

      

        
Cuando una tarea programada (o el chat) necesita tu permiso, además de aparecer acá puede avisarte a tu canal con links de un solo uso para permitir o denegar desde el teléfono.

        
        
        
      

      

        
Proveedor, modelo y API key tienen su propia ventana (también la pill proveedor · modelo de la barra).

        

      

      

    

  

  

    

      
proveedor

      
Modelo

      
Elegí con qué modelo trabaja el agente. La API key queda en lampson/.lampson/config.json, solo en esta máquina; nunca vuelve al navegador.
